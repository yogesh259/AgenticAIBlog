The guardrail stack, in run order

The nodes create_agent built for the healthcare assistant, from get_graph(). Pick a request to see which nodes it passes, in what order, and what each guardrail does.

Request

  1. __start__

    then HealthcareSafetyFilter.before_agent
  2. HealthcareSafetyFilter.before_agentinput check

    then PIIMiddleware[email].before_model, or MedicalOutputValidator.after_agent on a jump to the end
  3. PIIMiddleware[email].before_modelcontext check

    then PIIMiddleware[credit_card].before_model
  4. PIIMiddleware[credit_card].before_modelcontext check

    then model
  5. model

    then HumanInTheLoopMiddleware.after_model
  6. HumanInTheLoopMiddleware.after_modelaction check

    then PIIMiddleware[credit_card].after_model
  7. PIIMiddleware[credit_card].after_modeloutput check, switched off

    then PIIMiddleware[email].after_model
  8. PIIMiddleware[email].after_modeloutput check, switched off

    then tools if the reply has tool calls, else MedicalOutputValidator.after_agent
  9. tools

    then back to PIIMiddleware[email].before_model
  10. MedicalOutputValidator.after_agentoutput check

    then __end__
  11. __end__

Observe: on the way in the hooks run in list order, on the way out in reverse: the approval check, listed after both PII middleware, is the first after_model node. A jump to the end skips the model but not after_agent.
