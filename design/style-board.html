Module 04 · Tools & ReAct Agents Lesson 4.3

The agent loop

How a tool-calling agent decides, acts, observes and repeats, and how LangGraph runs that loop with two nodes and one conditional edge.

Concept + code Needs: 4.2 Binding tools LangGraph 1.x
In short
  • An agent is a loop: the model either answers or asks for a tool, and every tool result goes back to the model.
  • In LangGraph the loop is two nodes (agent, tools) plus one conditional edge (tools_condition).
  • State only grows: each node returns new messages and the add_messages reducer appends them.

Why it matters

A plain LLM call can only answer from what the model already knows. An agent can also act: it asks for a tool, reads the result, and decides again. That decide → act → observe cycle is the agent loop. Almost every pattern later in the course (agentic RAG, multi-agent teams, human-in-the-loop) is built on top of it.

    Ready

    Observe: the state never shrinks. Each node returns only its new messages and the add_messages reducer appends them. The loop ends the first time the model replies without a tool call.

    Code walkthrough

    Run the graph once and print every message in the final state.

    Gotchas

    Forgot bind_tools?Without .bind_tools([...]) the model never sees the tool schemas. It never asks for a tool, so tools_condition always routes straight to END.

    Key ideaNodes don't edit the message list. They return new messages, and the reducer decides how those merge into state.

    TipCap runaway loops with graph.invoke(inputs, config={"recursion_limit": 10}). LangGraph raises GraphRecursionError when the limit is hit.

    NoteThis is the same loop the prebuilt agent builds for you. Lesson 4.4 shows the one-line version.
